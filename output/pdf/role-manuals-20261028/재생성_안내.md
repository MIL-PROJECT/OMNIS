# 역할별 사용자 매뉴얼 재생성 안내

이 폴더는 2026-10-28 Windows 격리 실행으로 확인한 OMNIS 1.0.0의 사용자 매뉴얼 자료입니다. 애플리케이션 소스 수정은 하지 않았습니다. PDF 생성은 앱 실행이나 외부 서비스 접속 없이 가능합니다.

## 먼저 열 파일

- 통합_역할별_사용자매뉴얼.pdf: 전체 역할, 공통 안내, 36개 상세 절차와 인계 시나리오.
- 역할명_ROLE_사용자매뉴얼.pdf: 공통 안내·용어집·제한사항을 포함한 독립 문서 5종.
- 사용자절차_검증결과.csv: 역할과 절차별 사전 조건, 조작, 예상·관찰 결과, 검증 수준, 근거.
- 역할별_권한_및_업무표.csv: 실제 코드와 주요 실행 경계를 대조한 권한표. 모든 조합을 UI로 시험한 것은 아닙니다.
- 검증_및_산출물_요약.md: 실행 범위, 실패 해석, 미검증 범위와 최종 품질 검사.
- 알려진_제한사항_및_미검증항목.md: 현재 사용 제약과 문의 기준.

## 편집 가능한 원본

각 PDF와 같은 이름의 Markdown은 읽기·직접 편집용입니다. 자동 PDF 생성의 기준 원본은 source/content.py, workflows.py, operations.py, admin.py, guide.py입니다. Markdown만 수정한 내용은 자동으로 PDF에 반영되지 않습니다. 구조화된 절차 목록은 사용자절차_원본.json에도 제공합니다.

source/build_manuals.py는 전체 문서 구성, 표, 클릭 목차, 책갈피, 내부 링크, 원본 화면의 확대·번호 표시를 생성합니다. 스크린샷은 screenshots/의 실제 실행 PNG를 사용합니다. 원본 PNG 자체를 합성하거나 바꾸지 않고 PDF에서 영역을 확대하고 번호를 겹쳐 표시합니다.

## PDF만 재생성

필수 환경: Windows, Python 3, reportlab, pypdf, pdfplumber, Pillow, 맑은 고딕 일반/굵게 폰트. 검수에는 Poppler의 pdftoppm이 PATH에 있어야 합니다. 이 작업에서는 Codex 제공 Python 런타임과 기존 라이브러리를 사용했습니다.

프로젝트 루트 PowerShell에서 실행합니다. 아래는 로컬 Python이 PATH에 있는 경우입니다.

```powershell
python -X utf8 output/pdf/role-manuals-20261028/source/build_manuals.py
python -X utf8 output/pdf/role-manuals-20261028/source/qa_manuals.py
python -X utf8 output/pdf/role-manuals-20261028/source/deliver.py
```

마지막 명령은 보완 검증표·현재 소스 차이·책갈피 검사·파일 목록·ZIP을 생성합니다. PDF 변경 후에는 전체 렌더 이미지와 주요 확대 페이지를 사람이 다시 확인해야 합니다. 자동 검사 성공이 시각 검수나 업무 정확성 검증을 대신하지 않습니다. 이번 시각 검수 기록은 evidence/visual-review.json에 보관합니다.

## 앱 검증을 다시 실행할 때

이 절차는 개발·검증 담당자용입니다. 사용자 본문에 있는 일반 사용 절차와 다릅니다. 프로젝트의 기존 node_modules와 Windows Electron 실행 환경이 필요합니다. ZIP은 의존성·빌드 번들·가상 DB·앱 캐시를 포함하지 않습니다. 압축을 푼 폴더는 원래 프로젝트의 output/pdf 아래와 동일한 깊이로 놓아야 기존 스크립트의 상대 경로가 맞습니다.

1. evidence/source-manifest.json의 커밋과 파일 해시를 확인합니다. evidence/snapshot은 이번 검증의 고정 소스입니다.
2. 새 검증은 별도 산출물 폴더에서 진행합니다. source/setup.py는 현재 저장소 소스를 다시 복사하므로 보존 중인 기준 스냅샷 위에서 무심코 실행하지 않습니다.
3. source/checks.mjs는 고정 소스의 타입·Lint·11개 테스트·seed·build와 5개 기존 E2E를 실행합니다. 재실행 명령은 `node output/pdf/role-manuals-20261028/source/checks.mjs`입니다.
4. source/ui-verify.mjs는 다섯 역할의 실제 Electron 화면을 Playwright로 조작합니다. source/supplement.mjs는 이어서 추가 검증하며, `node .../source/supplement.mjs UI20`은 첨부 절차만 재검증합니다.
5. source/probe.mjs는 UI만으로 확인하기 어려운 권한·날짜·마감·수정·초기화·첨부 경계를 내부 호출로 확인합니다. UI 실행 검증과 구분해야 합니다.
6. 프로젝트 테스트 실행기는 OMNIS_E2E_DATA를 사용하여 앱의 userData를 격리합니다. 실행 중 app.getPath('userData')가 가상 프로필 경로인지 검증합니다. 운영 APPDATA 경로나 운영 DB로 바꾸지 않습니다.
7. 이번 source/supplement.mjs는 이전 UI 결과의 dataDir를 읽습니다. ZIP에는 가상 프로필 DB가 없으므로 먼저 새 UI 검증을 실행해야 합니다.

파일 선택·저장 대화상자는 경로를 반환하는 테스트 대체를 사용했습니다. 버튼 동작, 첨부 복사·삭제, CSV/PDF 생성은 확인했지만 OS 선택창과 기본 연결 앱 실행은 직접 검증하지 않았습니다. UI14는 조회전용 AI 분류를 허용한다고 잘못 기대한 테스트가 실패한 기록이며 UI17에서 정상적인 권한 거부를 재확인했습니다. UI20은 전환 대기 문제 이후 재실행하여 통과했습니다. 실패 원본은 삭제하거나 성공으로 바꾸지 않았습니다.

## 폴더와 개인정보

- evidence: 실행 로그·결함 재현·소스 기준·PDF 검사 결과. 운영 데이터가 아닌 가상 검증 자료입니다.
- screenshots: 실제 실행 화면 원본. 미사용 보조 캡처와 오류 캡처도 포함합니다.
- rendered-final: 최종 PDF 전체 페이지 PNG·접촉 시트 및 확대 검수 이미지. ZIP에는 접촉 시트와 확대 이미지 중심으로 포함합니다.
- diagrams: 매뉴얼에 수록한 설명 도식의 별도 PNG.
- source: 문서 생성·검증·패키징 코드. 앱 소스 수정용 패치가 아닙니다.

ZIP에서는 node_modules, out, 앱 캐시, 사용자 프로필, DB, 이전 렌더 결과, 임시 편집 스크립트를 제외합니다. 소스에 나오는 demo 비밀번호는 프로젝트가 제공한 합성 테스트 계정용이며 실제 사용자 비밀번호가 아닙니다. 문서와 캡처에 운영 비밀번호·토큰·실제 사용자 데이터는 넣지 않았습니다.
