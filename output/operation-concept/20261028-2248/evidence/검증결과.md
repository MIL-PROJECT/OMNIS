# 검증결과

최종 확인 대상은 출력 폴더 최상위의 HWP·DOCX·PDF 세 파일입니다. 세 파일 모두 18쪽입니다.

## 형식과 내용

- DOCX: Word 16.0 읽기 전용 재열기·재페이지화 성공. 편집 문단 138개, 표 17개, 그림 10개.
- HWP: 한글 2022 실제 저장·재열기 성공. OLE/CFB 디렉터리에서 FileHeader·DocInfo·BodyText·Section0을 확인했습니다. FileHeader의 HWP Document File 식별값과 압축 스트림 정상 해제를 확인했습니다.
- PDF: 최종 HWP에서 한글 2022로 직접 내보냈습니다. Word 검증 PDF는 evidence/docx-native.pdf이며 제출 PDF는 최상위 파일입니다.
- Word·HWP·PDF와 canonical content.json의 본문·제목·표 셀·캡션 대조에서 누락 0건. HWP 저장 전후 텍스트가 일치합니다. PDF의 대체 문자 0개입니다.
- 인적사항 4열·머리행+참가자 3개 행, 모든 참가자 입력 칸 공란을 확인했습니다.
- 본문 1~5의 원문 항목과 AI 활용 4열 표를 유지했고, 부록은 5번 뒤에 배치했습니다. 그림 1~10은 본문 등장 순서입니다.

## 렌더링과 육안 검사

- Word의 지원되는 SaveAs2(PDF)와 한글 내보내기를 각각 사용했습니다.
- 기본 render_docx.py는 LibreOffice 미설치로 실행할 수 없어 원인 로그를 확인한 뒤 설치된 Word·한글의 정식 변환 경로와 Poppler를 사용했습니다.
- 두 PDF의 모든 18쪽을 120dpi PNG로 렌더링하고 18개 비교 이미지(Word/HWP 각각 전 페이지)를 원본 해상도로 확인했습니다.
- 한글·표·그림·캡션·쪽 번호를 점검했고 빈 페이지, 본문 잘림, 겹침, 고아 제목이 발견되지 않았습니다.
- 앱 간 자간·줄바꿈·표 행 높이·그림 안티앨리어싱은 일부 다릅니다. 본문 내용·표·그림·쪽 수는 동일합니다. HWP와 최종 PDF를 최종 편집·제출 기준으로 사용합니다.
- 초안 도식의 제목 겹침, 캡처 탭/설명 불일치, 그림 번호를 수정하고 최종본을 재검증했습니다.
