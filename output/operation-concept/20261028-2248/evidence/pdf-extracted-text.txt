나. 체계 주요기능① 정보통신 운영현황 입력 및 시현관리자는 체계·상태·운용률·비고를 등록·변경하고 사용자는 통합상황판에서 집계와 상세 목록을 확인한다. 상황경보는 종류·중요도·발생시각·영향·조치 안내를 입력하여 관리한다. GPS 전파교란 유형도 수동 등록하는 상황 항목이며, 센서가 실제 전파를 탐지하는 기능을 뜻하지 않는다. 화면 집계는 저장된 가상 자료를 반영하며 실부대 운용률이나 실측 가용도를 증명하지 않는다.② 고장 접수부터 검증 및 종결까지 관리등록자는 제목·증상·접수수단·중요도·대상 체계·요청부서·신고자·장비·서비스 영향·발생시각을 입력한다. 접수수단의 게시판은 게시판으로 접수된 건임을 구분하는 값이다. 외부 게시판을 자동 수집하거나 연동하는 기능은 아니다. 입력 점검과 템플릿으로 확인할 질문을 제시하며 저장 전 작성자가 내용을 수정할 수 있다.관리자는 분류 후 조치부서와 담당자를 별도로 지정한다. 부서 미지정은 요청부서로 대체하지 않고 미지정 상태로 표시한다. 정비 담당자는 원격 또는 현장 조치를 선택하여 원인·조치·결과를 기록하고, 검증 후 종결로 진행한다. 허용되지 않은 상태 이동은 차단하며 보류·취소·재조치도 이력으로 남긴다.
그림 3. 최신 Windows 패키징 앱의 신규 접수 화면 일부. 별도 가상 프로필로 촬영했으며 편집 가능한 입력과 로컬 보완 기능을 확인한다.긴급 선조치 건은 사유와 실제 조치 시작시각을 사후 기록하여 접수시각과 구분한다. 이는 앱이 장비를 직접 복구했다는 의미가 아니다. 고장 결과 검증도 입력된 결과의 업무 확인이며 실물 시험의 대체가 아니다.

③ 정비 등록과 일정 및 실적 관리관리자·정비 담당자는 정비 종류, 우선순위, 예정일·기한, 대상 체계, 담당자 및 내용을 등록한다. 고장에 연결한 비계획 작업과 정기 계획 작업을 구분하고 목록·캘린더에서 진행 상황을 확인한다. 착수·보류·완료 기록과 결과를 남기므로 예정 건수와 완료 건수를 같은 것으로 집계하지 않는다.등록·편집 과정은 기존 역할 정책을 따른다. 필수 체크리스트가 남은 완료 요청은 검증으로 막고, 보류된 작업은 재개 후 완료하도록 상태 전이를 통제한다. 월 단위 일정 조회와 일일·주간 실적 보고는 구분한다. 별도 정비 요청의 관리자 승인 단계와 월간 보고 완결성은 보완 대상이다.④ 계획 및 비계획 작업 통제와 일일 마감통제 담당자는 08:30에 계획·비계획 작업 수를 확인하고 업무 중 변동을 반영한다. 16:00에는 실제 작업 상태와 보고 수치를 대조하여 완료·미완료·이월 사유를 정리한다. 정합성 확인 뒤 일일 마감과 인수인계 초안을 작성하고 담당자가 확정한다. 숫자를 입력하는 행위와 실제 조치 완료를 분리하여 미종결 건의 은폐를 줄인다.
그림 4. 통제·일일마감 화면 일부. 격리된 가상 DB의 계획·실적 대조 화면이며 참고 사례의 실제 군 시스템 화면은 아니다.제한 사항  DELIIS 자료의 직접 읽기·쓰기나 자동 정산은 구현되지 않았다. 원문 사례의 대조 절차를 로컬 앱에서 지원하는 수준이며, 타 체계의 공식 기록을 대체한다고 주장하지 않는다.

⑤ 근무 편성과 지시사항 관리관리자는 근무 일자·교대·직책·담당자를 등록·수정·삭제하고 다중 담당자를 편성한다. 소속 조직을 선택하면 해당 조직의 가상 담당자 명부를 조회하고 근무 등록으로 연결한다. 명부는 오늘 근무 등록 여부와 독립적으로 조회하므로 편성 전 담당자 확인이 가능하다. 명부 인원과 당일 근무 인원을 동일하게 표시하지 않는다.지시사항은 내용·발행·기한·중요도·담당·상태와 확인 기록으로 관리한다. 확인하지 않은 지시는 내 업무에서 확인 대상으로 제시한다. 다만 전체 정원·현원·휴가·파견 등을 집계하는 병력 현황 체계가 구현된 것은 아니다. 실제 편제·인원 자료는 사용하지 않고 가상 조직과 가상 담당자로 시연한다.⑥ 보고서와 사용자 지원일일·주간 업무 현황을 집계하고 CSV/PDF 내보내기를 제공한다. 보고서의 범위와 기준일은 저장된 업무 자료에 따른다. 현재 월 단위 캘린더를 월간 보고서 전체 구현의 근거로 대신하지 않는다. 사이드바에서 역할별 사용자 매뉴얼 PDF를 내려받을 수 있다. 기존 매뉴얼은 보존된 작성 시점의 자료이며 최신 화면과 차이가 있을 수 있다.⑦ 권한과 기록 및 데이터 보존
화면 버튼을 숨기는 것에 그치지 않고 Main 서비스에서도 역할과 대상 접근을 검증한다. 사용자 가입 승인과 정비 요청 승인은 다른 업무이다. 감사·상태 이력, 로컬 백업 및 복구 기능을 통해 누가 어떤 처리 상태를 변경했는지 확인한다. 복구가 모든 PC·모든 장애 상황에서 검증되었다고 확대 해석하지 않는다.저장과 배포  현재 Windows 1.0.1 설치본은 생성되었고 패키징 앱 시험 기록이 있다. 설치 파일은 미서명이다. 새 PC의 모든 보안 정책·설치 업그레이드 및 macOS 실기기 동작을 이번 문서 작성으로 재검증한 것은 아니다.

다. 운용개념 및 운용 시나리오1) 일반 고장 접수와 조치 및 종결입력 예시: 제목은 “체계1 장비A 연결 불가”, 증상은 “가상 화면 응답이 없고 재시도 후에도 동일함”, 영향은 “가상 단말 한 대”로 한다. 실제 망 구성·위치·인증정보는 입력하지 않는다. 요청부서는 가상 A조직으로 두고 조치부서는 접수 단계에서 미지정으로 둘 수 있다.
2) 긴급 선조치 후 사후 접수업무 영향으로 선조치가 필요했던 상황을 가정한다. 담당자는 실제 수행한 행위만 기록하고 긴급 사유와 실제 조치 시작시각을 입력한다. 관리자는 사후 접수 내용과 중복 건을 확인하여 담당과 후속 작업을 정리한다. 필요하면 비계획 정비로 연결하고, 결과 검증과 종결 절차를 생략하지 않는다.예외와 책임  미지정 건은 미지정으로 남기며 임의 담당자를 추정하지 않는다. 조치가 끝나지 않으면 완료로 바꾸지 않고 보류·추가 조치 또는 인계 사유를 기록한다. 앱의 기록 시간은 현장에서 실제 확인한 시간과 구분하여 입력한다. 상태 전이 검증은 허용되지 않은 지름길 처리를 차단하는 통제이다.
단계담당 역할화면 및 처리 확인 기록접수등록자템플릿 또는 직접 입력 후 증상·영향을 확인하여 저장접수번호·시각·원본 내용분류관리자일반/긴급 및 업무 분류를 확인한다. AI는 선택 사항이다. 분류·근거·검토 여부배정관리자소속 조직→조치부서→담당자를 선택하여 명시적으로 배정 요청부서와 별도 배정값조치정비 담당원격/현장 작업과 원인·조치 내용을 기록시작·결과·상태 이력확인권한 있는 담당조치 결과를 검증하고 필요하면 재조치검증 시각·확인 내용종결권한 있는 담당검증 상태에서 종결하고 미완료 건과 분리종결 시각·처리 이력

3) 계획 및 비계획 정비와 일일 통제
반복 작업의 미리보기는 실제 작업 생성과 다르다. 생성 후에도 체크리스트 수행과 완료 확인이 필요하다. 정기 작업이 존재한다는 이유로 완료 수를 늘리지 않는다. 정합성이 맞지 않으면 원인을 확인하고 정정한 뒤 마감한다.4) 선택형 AI 지원과 사람 검토기본 시연은 LOCAL로 진행한다. 담당자가 제목·증상·영향을 작성하면 입력 보완 도우미가 먼저 질문을 제시한다. 확인한 답변을 추가하거나 미확인으로 표시한 뒤 분류를 실행한다. 결과의 분류·긴급도·추천 팀·추정 시간·근거를 읽고 실제 적용 여부를 결정한다.외부 Provider를 사용할 때는 관리자가 별도 활성화와 동의를 저장한 상태여야 한다. 현재 입력을 최소화·마스킹한 뒤 요청하고 구조화 출력 및 후보 ID를 검증한다. 실패하면 LOCAL 결과를 반환하며 선택한 Provider, 실제 Provider, 대체 여부를 함께 보여준다.
