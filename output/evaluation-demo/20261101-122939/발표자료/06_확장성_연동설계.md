# 확장성과 타체계 연동 제안

기준: 2026-11-01, OMNIS 1.1.0 / schema 9. 이 문서의 staging, 멱등 교환, 중앙화, API·이벤트는 **향후 설계안**이다. 외부 체계 API를 호출하거나 새 제품 기능을 구현한 결과가 아니다.

## 현재 구조와 변경 영향

| 확장 대상 | 재사용할 경계 | 필요한 추가 개발과 확인 |
|---|---|---|
| 새 점검 업무 | Renderer→Preload→IPC→Main 서비스 | 입력·응답 계약, 채널 등록, 역할/대상/상태 조건, DB 이관, UI, 감사, 회귀 |
| 새 AI 제공자 | AIProvider / Factory / Orchestrator | 설정·인증·호출·반환 변환, 모델별 출력·후보 ID 검사, 오류·시간·비용·현장 품질 시험 |
| 여러 PC | 도메인 서비스의 업무 규칙 | 중앙 API·인증·DB, 트랜잭션·버전 충돌, 장비 동기화, 오프라인 정책, 관측·복구 |
| 타체계 교환 | 문서상의 MaintenanceExchangeAdapter | 상대 데이터 계약, 원본 책임, staging/preview/apply, 식별자 매핑, 승인·멱등·재처리 |

현재 AppService에 책임이 집중되고 일부 서비스가 직접 SQL을 쓴다. 전면 재작성보다 업무별 서비스와 저장소 경계를 테스트로 고정하며 분리한다. 기존 업무 요청과 데이터 의미를 보존해야 한다. SQLite WAL과 busy timeout은 로컬 동작 설정이며 다중 PC 보장 수치가 아니다.

## 대표 교환: 외부 정비 결과를 기존 접수 건에 연결

첫 단계는 **외부 결과의 단방향 반입 제안**으로 제한한다. OMNIS 접수 상태의 최종 책임은 OMNIS에 두고, 외부 정비 결과를 증빙·검토 대상으로 연결한다. 외부 결과가 접수 상태를 무조건 CLOSED로 바꾸지 않는다. 반대 방향 내보내기나 양방향 상태 동기화는 별도 계약이다.

아래는 실제 상대 체계의 규격이 아닌 합성 예시다.

```json
{
  "schemaVersion": "proposal-1",
  "batchId": "demo-batch-001",
  "sourceSystem": "EXAMPLE-MAINT",
  "generatedAt": "2026-11-01T03:00:00Z",
  "records": [{
    "externalId": "DEMO-RESULT-001",
    "revision": 1,
    "operation": "UPSERT_RESULT",
    "targetIncidentExternalRef": "DEMO-INCIDENT-001",
    "sourceUpdatedAt": "2026-11-01T02:50:00Z",
    "resultCode": "ACTION_RECORDED",
    "resultText": "가상 케이블 접점 정비 후 관찰 기록",
    "attachmentRefs": []
  }]
}
```

| 항목 | 합의할 계약 |
|---|---|
| 식별·매핑 | `(sourceSystem, externalId)`와 내부 record ID를 명시 매핑. 이름·제목·시간 유사성으로 자동 연결하지 않음 |
| 상태 코드 | 상대 코드→내부 의미의 버전별 매핑. 미지정/알 수 없는 코드는 오류로 분리하고 담당자 확인 |
| 원본 책임 | 외부 결과 원문과 revision은 송신측, 접수 상태·승인 결정은 OMNIS. 필드별 책임 표 확정 |
| 시간 | UTC ISO 8601과 발생/변경/수신 시각 구분. 표시 시간대 별도. 시계 오차 허용 범위 합의 |
| 파일·첨부 | 크기·유형·인코딩·압축폭탄·경로 이탈·악성 파일 검사. 정책상 허용된 자료만 취급 |
| 내용 최소화 | 업무에 필요한 필드만 반입. 민감 자료 표시·접근·보존·파기 책임을 조직 정책과 합의 |

## 반입 처리와 트랜잭션

1. 원본 파일을 제한된 영역에 보관하고 SHA-256·수신자·수신시각을 기록한다. 해시는 원본 동일성 보조 수단이며 송신자 진위를 단독 보증하지 않는다.
2. `staging`에서 스키마·크기·필수항목·중복·코드·매핑·시간·revision을 검증한다. 검증 실패 자료는 업무 테이블에 쓰지 않는다.
3. 미리보기에 추가/변경/무시/충돌/오류 행과 사유, 예상 상태 영향을 보여 준다. 승인 시 Main 권한과 당시 데이터 version을 재검사한다.
4. 최초 단계는 **승인 batch 전체 원자 적용**을 기본안으로 한다. 한 행 충돌 시 전체 업무 변경을 롤백하고 실패 원인을 보존한다. 대용량 행별 부분 적용이 필요하면 성공/실패 명세와 재처리 의미를 별도 버전으로 합의한다.
5. 멱등 키와 내용 hash, 외부/내부 식별자, 승인자·시각, before/after, 업무 이벤트를 같은 논리 트랜잭션으로 남긴다. 첨부 파일 이동은 staging 및 보상·고아 정리 절차를 별도 설계한다.
6. 완료 영수증에 batch ID, applied/skipped/rejected, 내부 참조와 오류 코드를 제공한다. 수신 성공과 업무 적용 성공을 분리한다.

## 멱등과 충돌

제안 키: `(sourceSystem, externalId, revision, operation)`.

- 같은 키·같은 정규화 내용: 이미 처리된 결과를 반환하고 업무를 다시 바꾸지 않는다.
- 같은 키·다른 내용: 송신 계약 위반 충돌. 자동 덮어쓰기 없이 보류한다.
- 더 낮은 revision: 오래된 변경으로 보류/무시 정책을 명시한다.
- 더 높은 revision: 내부 예상 version과 업무 상태를 다시 확인한 뒤 승인한다. 종결 자료 정정은 별도 권한·사유·이력 경로가 필요하다.
- 파일 hash가 같아도 다른 batch는 가능하고, 파일 형식이 달라도 같은 업무 변경은 가능하다. 파일 hash를 업무 멱등 키로 대신하지 않는다.
- 승인 후 전송 확인 전에 중단된 경우 재시도는 기존 처리 결과를 조회한다. 네트워크 전달의 exactly-once를 주장하지 않고, 재전달을 허용하면서 업무의 중복 효과를 막는 것을 목표로 한다.

## 실패·운영·인증

일시 오류는 횟수·대기·최대 경과시간을 제한해 재시도한다. 검증·권한·충돌 오류는 자동 재시도하지 않는다. 격리 대기열과 담당자 재처리 화면, 원본/결과 보존기간, 운영자 역할 분리를 합의한다. 중앙 API 도입 시 서비스 계정·최소 권한·자격정보 회전·상대 인증·전송 보호·요청 재전송 방지·접속 감사가 필요하다. 구체 인증 방식은 상대가 제공하는 승인 규격에 따라 정한다. 특정 국방 체계의 승인된 인증 방식이 확인되었다는 뜻이 아니다.

연결은 승인된 망과 접속 경로에서만 설계한다. 조직이 승인하지 않은 라우팅·보호조치 우회는 포함하지 않는다. 장애 시 로컬 기본 업무는 계속할지, 교환 대기 중 수정을 허용할지와 사후 충돌 해소 주체도 합의해야 한다.

## 단계별 진입·완료 조건

| 단계 | 진입 조건 | 완료 판정 |
|---|---|---|
| 0. 업무 계약 | 데이터 소유자·승인 담당·허용 망·교환 범위 합의 | 코드·식별자·원본 책임·보존·오류 계약 승인 |
| 1. 파일 교환 | 합성 표준/오류/중복/충돌 자료 준비 | 미승인 쓰기 0, 재반입 중복 효과 0, 실패 롤백·영수증 대조 통과 |
| 2. 어댑터 | 파일 단계 시험·업무 승인 통과 | 반복 교환·재처리·관측·권한 회귀 통과 |
| 3. API/이벤트 | 상대 공식 규격·접근권·인증·운영 책임 확정 | 종단 정합성·중단 복구·재전달·지연 도착·순서 역전 시험 통과 |
| 4. 여러 PC | 현장 동시 수정·오프라인 요구 확정 | 중앙 인증·충돌·복구·부하 수용 기준을 측정하여 통과 |

## 실증 지표와 측정 방법

수치 개선은 아직 측정하지 않았다. 동일한 합성 과업과 난이도, 사전에 정의한 평가표로 기존 방식과 OMNIS를 비교한다. 순서 학습 효과를 줄이도록 수행 순서를 바꾸고 평가자 판단 불일치를 기록한다. 개인정보 없는 과업 자료·원시 결과·오류를 보존한다.

| 지표 | 분모·관측 방법 |
|---|---|
| 필수 기록 누락률 | 누락 필수 필드 / 해당 과업에 적용되는 필수 필드 |
| 상태 정합률 | 정의된 업무 불변식을 만족한 사례 / 검사 사례 |
| 인수인계 누락률 | 다음 근무에 전달되지 않은 필수 항목 / 전달 대상 필수 항목 |
| 과업 시간 | 동일 시작/종료 조건, 중간값·분포·실패율을 함께 제시 |
| 추천 타당성 | 전문가 합의 정답과 추천 비교, 업무별 오분류·미지원 항목 구분 |
| 오반영률 | 부적절하다고 평가된 추천 중 실제 반영 건 / 검토한 부적절 추천 건 |
| 장애 대응 | 제공자 실패·오류·지연 중 기본 업무 성공, 복귀 경로와 기록 대조 |
| 운영 복구 | 격리 복구 시험에서 자료 손실 범위·복구시간 측정, 목표 RPO/RTO는 운영자와 합의 |

표본 수와 수용 기준은 현장 위험도·과업 다양성에 맞춰 사전 확정한다. 테스트 통과 건수나 UI의 신뢰도 값을 위 지표로 대체하지 않는다.
