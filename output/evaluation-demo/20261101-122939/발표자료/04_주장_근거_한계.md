## 확인한 실행 증빙

- `evidence/context.json`: HEAD·tree·버전·촬영 조건. 현재 main과 검증 PR head의 source tree가 동일하다.
- `evidence/installed-build.json`: 설치 앱의 Main/Preload/index.html 3개 파일이 현재 빌드와 SHA-256 일치. 앱 전체 파일 동일성 증명으로 확대하지 않는다.
- `evidence/pr-ci.json`: [GitHub CI run 41268151403](https://github.com/alex50027319/military_project/actions/runs/41268151403)의 arm64/x64 작업 성공.
- `evidence/admin-e2e-source.json`, `admin-e2e-packaged.json`: 기존 관리자 E2E 각각 8개 check, errors 0. 7영역×4크기 check 포함.
- `recordings/capture.json`: 현재 촬영의 업무 호출, 분석 전후 필드 비교, 실제 LOCAL 복귀, 명시적 반영 이력.
- `recordings/control-capture.json`: 수동 합성 계획 입력 후 실제 통제 화면.
- `recordings/history-capture.json`: 선택/실행 Provider를 보여 주는 실제 앱 화면.
- `evidence/filming-limitation.json`: 체계 미지정 분석 입력 오류 재현. 촬영 완료를 위해 체계를 명시한 가상 사례 사용. 제품 수정은 하지 않음.

## 알려진 결함과 검증 공백

체계 미지정 접수는 `selected.system_id=null`을 AI 입력으로 전달하지만 `ai:triageIncident`는 string 또는 omitted만 허용한다. 이 경우 분석이 입력 검사에서 거절된다. 실제 오류 화면을 보존했다. 추후 수정 시 null/undefined 정규화와 체계 지정·미지정 회귀가 필요하다. 이 오류는 정상 응답 성공으로 처리하지 않았다.

생성형 모델 의미 정확도, 실제 유료 API, 타체계 종단 연동, 다중 PC 동시성, 현장 처리량·복구시간은 미검증이다. 새 PC 설치·조직 보안 적합성·Apple 배포 서명/공증도 시험 성공과 구분한다.
