# 상영·재촬영·운영 절차

## 상영

최종 MP4 한 개에 한국어 음성과 자막이 들어 있다. 15분 상영 시 별도 WAV/SRT를 함께 틀지 않는다. SRT는 자막 없는 새 편집본을 만들거나 음성 내용을 검색할 때 쓴다. 이미 자막이 보이는 MP4에 플레이어의 외부 SRT를 또 켜면 이중 표시된다.

발표 전 로컬 동영상 플레이어에서 처음·중간·마지막을 재생하고 한글 자막과 스피커 음량을 확인한다. 발표 기기는 16:9 화면과 오디오 출력을 사용한다. 영상의 차트·도식은 설명 자료이며, 실제 앱은 05·11·12·13·14·15 장면이다. 로컬 파일을 복사해 상영하면 네트워크 연결에 의존하지 않는다. USB 등 반입 매체는 행사 규칙을 따른다.

영상이 재생되지 않으면 발표 대본과 `도식/`의 PNG 또는 `장면_미리보기/`를 화면에 띄우고 큐시트 시간 배분으로 설명한다. 음성 문제만 있으면 내장 음성을 끄고 대본을 읽는다. 이 대체 진행에서 실시간 앱 연결 성공을 주장하지 않는다.

## 촬영 조건과 공개 범위

- 실제 `/Applications/OMNIS.app` v1.1.0을 Playwright Electron으로 촬영했다. 화면을 흉내 낸 HTML·합성 UI를 실제 앱처럼 제시하지 않았다.
- `OMNIS_E2E_DATA`를 새 절대 경로로 지정해 기존 userData와 분리했다. 새 가상 접수·계정·부서를 사용했다. 기존 사용자 DB를 초기화하거나 수정하지 않았다.
- 사례의 상태 진행과 통제 계획 숫자 일부는 검증된 Main IPC 호출로 준비했다. AI 분석·반영, 오류 복귀, 관리자 잠금·해제는 실제 앱 UI를 조작했다.
- 원본은 1440×768이다. 영상은 관심 영역을 잘라 1920×1080 설명 화면에 배치했다. 실제 화면 값을 새로 그리지 않았으며 읽기 시간을 위해 끝 프레임을 유지했다. 녹화 도구의 상단 action tooltip은 crop 밖이다.
- LOCAL 분석은 결정적 규칙이다. Ollama 장면은 미기동 loopback 주소에서 실제 연결 실패를 만든 것이며 생성형 응답 성공 장면이 아니다. OpenAI·Anthropic 유료 API를 호출하지 않았다.
- 계획 2 / 비계획 1 / 완료 2 / 이월 1은 수동 합성 fixture다. 관측 성능·자동 집계·현장 실적 수치가 아니다. 녹화 중 실제 일일 마감은 실행하지 않았다.
- 대본의 한국어 음성은 macOS Yuna 합성 음성이다. 발표자의 실제 녹음 또는 특정 인물 음성 복제가 아니다.

## 동일 환경에서 다시 만들기

현재 결과는 `sources/`의 content.py, voice.py, render_slides.py, compose.py, documents.py와 capture*.mjs로 추적할 수 있다. 의존성은 기존 저장소의 pnpm/Playwright/Electron, Pretendard와 기존 `release/demo-video/tools`의 Pillow·imageio_ffmpeg다. 앱 버전과 실행 경로가 바뀌면 먼저 증빙을 갱신해야 한다. scripts에 저장된 ROOT는 이 작업 폴더다.

1. 제품 소스와 버전, `git status`, 설치 앱의 Main/Preload 파일 hash를 확인한다. 실제 운영 앱을 종료해야 하는지 운영자와 조율하고, 촬영 스크립트가 기존 userData를 지정하지 않는지 확인한다.
2. `sources/capture.mjs`가 새 timestamp 하위 profile을 쓰는지 검토한 후 `node sources/capture.mjs`를 실행한다. 앱 가상 로그인 정보는 기존 테스트 fixture용이며 실제 계정 자격정보를 넣지 않는다.
3. 촬영 manifest의 profile에 맞춰 supplemental capture_history.mjs / capture_control.mjs가 올바른 격리 프로필을 지정하는지 수정·검토하고 실행한다. 실패한 녹화의 manifest를 성공 자료로 재사용하지 않는다.
4. `python3 sources/content.py` → `PYTHONPATH=.../release/demo-video/tools python3 sources/voice.py` → 같은 PYTHONPATH로 `render_slides.py` → `compose.py` 순으로 실행한다. Yuna와 Pretendard가 필요하다. 기존 raw video와 타임베이스가 바뀌면 compose.py crop/offset도 다시 검토한다.
5. 영상 또는 오디오 원문을 수정하면 해당 WAV/AIFF 캐시를 문장 기준으로 갱신하고 `compose.py --force`로 영상 장면을 재생성한다. UI crop을 바꾸면 `segments/ui-*.mp4` 캐시도 명시적으로 제거 후 재생성한다. 제품 파일은 삭제하지 않는다.
6. `documents.py`로 대본·스토리보드·근거표를 갱신하고 `verify.py`로 최종 파일을 검사한다. QA 보고서는 결과값을 읽어 갱신한다. 생성 스크립트의 검사 성공만으로 사람의 청취·상영 환경 검토를 대신하지 않는다.

명령은 이 release 폴더 기준이다. 의존성 설치·제품 빌드·패키지 변경·유료 API 호출은 이 영상 제작에 포함하지 않았다. 다른 Mac에서 실행할 때는 절대 경로·서체·say 음성·Electron 버전을 먼저 맞춘다.

## 실패 시 대응

| 증상 | 판단과 복구 |
|---|---|
| 체계 미지정 AI 분석이 string/null 오류 | 알려진 입력 계약 불일치다. 촬영은 체계를 명시한 가상 사례 사용. 수정 작업은 별도 진행하고 지정/미지정/취소/재분석 회귀 필요 |
| 선택 모델 연결 실패 | LOCAL 복귀와 selected/actual Provider, error code, fallback 여부를 이력에서 확인. 이것을 생성형 모델 성공으로 설명하지 않음 |
| 앱이 기존 프로필로 열림 | 즉시 촬영 중단. OMNIS_E2E_DATA와 launch 환경을 확인. 실제 DB를 demo:reset하지 않음 |
| 관리자 변경이 거절됨 | 역할·계정상태·재인증·동시 수정 version 확인. UI에서 재조회하고 사유를 남김. 직접 DB 수정으로 우회하지 않음 |
| 정합성 경고가 표시됨 | 미해결 사례가 실제 표시되는 것이 맞다. 숨기거나 마감 완료로 부르지 않음. 예외 승인 여부는 업무 정책에 따라 별도 설명 |
| 한글 깨짐·자막 겹침 | Pretendard 설치와 ASS fontsdir 확인, 최종 프레임 다시 추출·검토 |
| 녹화가 짧거나 원본 좌표가 바뀜 | UI edit spec의 start/end/offset을 재계산. 정지 화면 유지와 생략 구간을 공개하고 잘못된 장면을 덧붙이지 않음 |

## 배포·데이터 관리

공유 ZIP은 최종 영상·음성·자막·발표 문서·도식·검증 요약만 포함한다. 실제/가상 프로필 DB, 자격정보 파일, 실패 녹화와 원본 디버그 tooltip 영상은 제외한다. 내부 제작자료는 release 폴더에 보존했다. 발표 자료의 장기 보존·외부 공유 범위는 사용자와 조직 정책에 따른다. 제품 코드 변경·Git commit·push는 이 작업에서 수행하지 않는다.
