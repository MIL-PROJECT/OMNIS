# OMNIS 실용 기능 5종 사용 안내

이 버전은 기존 업무·화면과 LOCAL/Ollama/OpenAI/Anthropic 기능을 유지하며 DB를 v6로 업그레이드한다. RAG는 포함하지 않는다.

## 1. 고장 접수 템플릿

1. **고장관리 → 신규 고장 접수**를 연다.
2. **자주 발생하는 고장**에서 인터넷, 통화, 전원, 무선, 영상, 프로그램 중 하나를 선택한다.
3. 작성 안내를 확인하고 **빈 항목 채우기**를 누른다. 기존 제목/구분을 바꾸려면 교체할 항목에 체크한다.
4. 증상과 서비스 영향을 직접 입력한다. 예시 안내는 실제 증상으로 저장되지 않는다.
5. **입력 내용 점검**에서 확인 질문에 답하거나 **확인하지 못함**을 선택한다.
6. **보완 내용 반영** 미리보기를 확인하고 접수를 저장한다.

템플릿 없이 자유롭게 접수해도 된다. 중요도·시각·담당자·실제 증상은 템플릿이 임의 확정하지 않는다. **되돌리기**는 적용 직전 값으로 돌아가므로 이후 수정도 되돌릴지 확인한다. **템플릿 연결 해제**는 작성한 일반 내용과 보완 답변을 지우지 않는다. 저장한 템플릿 버전과 질문은 당시 사본으로 보존된다.

ADMIN은 **시스템관리 → 업무 템플릿**에서 제목·분류·안내·질문·활성 여부를 수정한다. 정비 점검표의 항목명·필수 여부·해당 없음 허용도 같은 화면에서 관리한다. 수정 내용은 앞으로 적용하는 업무에만 반영된다.

## 2. 내 업무

**통합상황판 → 내 업무**를 누른다.

- 배정받은 미종결 고장. USER는 **내가 접수한 고장**으로 표시한다.
- 오늘 예정된 내 정비.
- 기한이 지난 미완료 내 정비.
- 내가 아직 확인하지 않은 직접 지정·동일 부서·전체 지시사항. 직접 지정 항목은 지정된 사람에게만 표시된다.

각 행을 누르면 해당 고장·정비·지시 상세가 열린다. 닫거나 업무를 처리하면 내 업무로 돌아온다. **지시사항 확인**은 열람 확인이며 지시의 이행 완료와 다르다. 만료된 공지는 제외한다. 지시의 완료 여부와 무관하게 유효하고 아직 확인하지 않은 공지는 확인 목록에 남을 수 있다.

날짜는 한국 업무일 기준이다. 작성자가 아니라 실제 담당자를 기준으로 집계한다. 자동으로 모든 정비반 작업을 개인 업무에 합치지 않는다. **새로고침**으로 최신 상태를 확인할 수 있다. 로그아웃 후 다른 계정에는 해당 계정의 조회 결과가 표시된다.

## 3. 정비 체크리스트

신규 정비 등록 시 기본 일반 점검표를 미리 선택한다. 작업 유형을 바꾸면 네트워크·통신·보안/프로그램에 맞는 점검표를 제안하며 직접 다른 점검표나 **없음 (기존 방식)**을 선택할 수 있다.

1. **정비관리 → 작업 상세 → 점검 항목**을 연다.
2. 항목별 **미확인 / 정상 / 이상 / 해당 없음**과 메모를 입력한다.
3. **점검 결과 저장**을 누른다. 저장된 값은 앱을 다시 실행해도 남는다.
4. 필수 항목을 정상 확인하고 기존 원인·상세 조치·작업 결과를 작성한 뒤 **완료**한다.

필수 미확인·이상 항목이 있으면 완료가 차단된다. **해당 없음**은 허용된 항목에서 사유를 입력했을 때만 인정된다. 선택 항목의 이상에도 조치 메모가 필요하다. 점검률과 기존 작업 진행률은 별개다.

기존 작업에는 점검표를 소급해서 붙이지 않는다. 연결하지 않은 작업은 이전 완료 절차로 처리할 수 있다. 권한 있는 담당자가 **점검표 추가**를 선택할 수 있고, 교체하면 결과가 초기화되므로 확인을 거친다. 완료·취소 작업은 수정하지 않는다. 템플릿 수정이 과거 점검 결과를 변경하지 않는다.

이 점검표는 시연용 일반 안내이며 장비별 공인 정비절차나 실제 장비 제어 기능이 아니다.

## 4. 반복 정비

1. **정비관리 → 반복 정비 → 반복 규칙 등록**을 누른다.
2. 작업명·유형·부서·담당자·체계·우선순위·체크리스트를 선택한다.
3. 시작일과 선택적 종료일, **매주/N주+요일** 또는 **매월/N개월+일자/마지막 날**을 설정한다.
4. **규칙 저장** 후 미리보기 기간을 선택하고 **일정 미리보기**를 누른다.
5. 생성할 날짜를 선택하고 **선택 작업 N건 생성**을 누른다.
6. 실제 생성된 작업은 기존 목록·캘린더·담당자의 내 업무에서 처리한다.

ADMIN은 활성 ADMIN/MAINTAINER 담당자를 지정할 수 있고 MAINTAINER는 자신이 만든 자기 담당 규칙만 관리한다. 비활성 담당자는 재지정해야 한다.

날짜·중복 정책:

- 주 시작은 월요일, N주 간격은 시작일이 속한 주 기준이다.
- 매월 31일이 없는 달은 말일에 생성하고 다음 달에는 원래 기준일로 복귀한다. 윤년도 반영한다.
- 미리보기 기본 30일, 최대 90일, 한 번 생성 최대 100건.
- 이미 생성·취소한 회차는 다시 만들지 않는다. 개별 작업의 예정일을 옮겨도 원래 회차는 중복 생성하지 않는다.
- 규칙 수정·중지·삭제는 이미 생성한 작업에 영향을 주지 않는다. 개별 작업 수정은 **이번 작업에만 적용**된다.
- 앱을 켰다는 이유로 작업을 자동 소급 생성하지 않는다. 과거 일정은 별도 확인 후 선택 생성한다. 마감된 날짜는 생성할 수 없다.
- 오래된 미리보기에서 확정할 때 규칙이 바뀌면 다시 미리보아야 한다.
- 일일 계획표의 수동 입력 건수에 자동으로 더하지 않는다. 규칙과 미리보기는 실제 작업 건수에 포함하지 않는다.

## 5. AI 입력 보완

고장 접수 화면, 고장 상세의 **AI 분류**, AI 지원의 **고장 분석**에서 사용한다.

- **입력 내용 점검**은 로컬 규칙으로 누락된 시각·범위·증상·영향·기존 조치를 확인한다. 외부 API 호출과 비용이 없다.
- 답변은 확인한 사실만 입력한다. 모르는 항목은 **확인하지 못함**으로 남긴다.
- **보완 내용 반영**은 분석에 사용할 답변을 반영한다. 본문을 계속 덧붙여 중복시키지 않는다.
- 실제 분석은 **AI 분류 / 분석 및 유사 고장 조회**를 눌렀을 때 실행한다. 부족한 정보가 있으면 **보완 후 분석** 또는 **현재 내용으로 분석**을 선택한다.
- 고장 상세의 보완정보는 기본적으로 분석용이다. 접수 수정 권한이 있을 때 **보완 답변 접수에 저장**을 별도로 누른다.
- AI 지원의 자유 분석 입력은 DB 자동저장하지 않는다. 로그아웃 시 사라진다.
- 외부 AI를 선택한 경우 분석 요청에 기존 동의·마스킹·timeout·요청한도가 적용되고 비용이 발생할 수 있다. 실패하면 LOCAL로 fallback한다.
- 입력을 바꾸면 이전 분석 결과를 최신 결과처럼 적용하지 않는다.
- 결과는 추천이며 기존 **검토 후 반영**으로만 업무에 반영한다. SLA 위험 계산은 기존 규칙을 사용한다.

## 저장·백업·권한

업무 데이터는 기존 userData의 SQLite DB에 저장하며 API Key 저장소와 분리한다. DB 전체 백업에 새 테이블도 포함된다. 템플릿과 업무 사본을 분리하고 반복 발생 회차의 유일성을 DB에서 검사한다. 오래된 체크리스트 저장은 다른 화면의 결과를 덮어쓰지 않고 새로고침을 안내한다.

**평가 시나리오 초기화**는 기존처럼 해당 시나리오 데이터만 정리한다. **전체 Demo 데이터 초기화**는 기존의 별도 위험 구역 기능으로, 확인·백업 후 사용자 입력 데이터 전체를 초기 상태로 되돌리는 동작이므로 구분해서 사용한다.

ADMIN 관리, 담당 MAINTAINER 처리, USER의 본인 접수 범위, VIEWER 업무 변경 금지를 Main에서 검사한다. 기존 시스템의 지시 열람 확인 권한은 유지된다.

## 5~7분 시연

1. 템플릿을 적용해 접수하고 확인 질문에 답한다.
2. AI 분류 결과를 검토한 뒤 정비 담당자를 지정한다.
3. 담당자 계정의 내 업무에서 고장 상세를 바로 연다.
4. 반복 정비를 저장하고 다음 일정을 미리본 뒤 담당자에게 생성한다.
5. 생성된 작업의 체크리스트 일부를 저장하고 다시 열어 복원되는지 확인한다.
6. 필수 항목이 남았을 때 완료 차단을 확인하고 모두 점검한 뒤 기존 결과를 작성해 완료한다.
7. 같은 반복 기간을 다시 미리보아 **이미 생성됨**을 확인한다.
