# 요청부서·조치부서 분리와 공군 조직별 선택

2026-10-28 변경. 기존 UI와 업무 workflow를 유지하며 DB v7에 조직 디렉터리를 추가했다.

## 최신 수정: 정보통신대대 및 실제 사용 DB 보완

공개자료에 세부 부서명이 없는 부대의 기본 조치부서를 사용자 요청대로 `정보통신대대`로 표시한다. `DEMO`와 안내 문구를 유지해 공식 확인 편제와 구분한다. 기존 `정보통신 업무 담당 (시연)` 기본 항목은 같은 team_id를 유지하며 이름만 갱신한다. 관리자 수정 명칭·비활성 상태·기존 배정은 보존한다. `organizations:list`에서도 누락된 기본 디렉터리를 보완하고 조치부서 목록을 열 때 재조회한다.

2026-10-28 실제 사용 DB 조사에서 실행 중인 개발 Main 프로세스와 DB가 이전 v7 상태였고 담당자 테이블이 없음을 확인했다. SQLite backup으로 `reports/local-repair/`에 먼저 백업한 뒤 v8 migration과 조직·가상 담당자 보완을 적용했다. 제2미사일방어여단의 `정보통신대대`, 제20전투비행단 담당자 10명, 기존 고장 53건의 요청부서·배정·상태 보존, integrity_check=ok를 확인했다. 실행 중이던 프로젝트 Electron 창은 정상 종료 후 최신 빌드로 다시 실행했다. 백업에는 사용자 데이터가 있으므로 Git에 포함하지 않는다.

이하 설치본 및 테스트 횟수는 각각 당시 버전의 기록이다.

## 최신 수정: 조치부서·담당자 조회

부대 담당자는 전체 사용자 목록을 필터하는 대신 선택한 부대의 `organizations:members`로 직접 조회한다. 조회 중/실패를 표시하고, 부대 변경 시 늦게 도착한 이전 조회 결과를 무시한다. 조회된 활성 담당자를 화면 사용자 목록에도 합쳐 오래된 화면 목록 때문에 배정 후 이름이 미지정으로 표시되는 것을 방지한다. Main의 명부 조회는 가상 담당자의 누락 슬롯을 보완하되 기존 수정·비활성 상태를 덮어쓰지 않는다.

기본 부대 22곳 모두 조치부서가 선택되도록 공개자료 확인 조직 13곳과 **시연용 담당창구 9곳**을 제공한다. 공식 명칭을 확인하지 못한 여단·전대 등은 `정보통신 업무 담당 (시연)`으로 명시하며 `DEMO` 등록 기준으로 구분한다. 실제 군 편제로 확인한 명칭이라는 뜻이 아니다. 기존 공통 정비반 3곳도 유지한다. 이미 관리자가 부서를 등록한 미확인 부대에는 기본 시연 창구를 추가 생성하지 않는다. 이하 이전 버전의 '미등록' 설명과 설치본은 당시 기록이다.

고장 상세에서 **부대급 → 소속 부대 → 조치부서 → 담당자**를 선택한 뒤 배정한다. 제20전투비행단·제2미사일방어여단의 담당자 10명과 조치부서 선택/저장, 재시작 보존을 E2E로 재현 검증했다. 이전 실행 파일이나 개발 Main 프로세스가 계속 열려 있으면 변경이 반영되지 않으므로 기존 앱을 완전히 종료한 뒤 이번 실행본으로 다시 시작한다. 데이터 초기화는 필요하지 않다.

최종 조회 수정본 검증(2026-10-28): typecheck/lint/build, 9개 파일 61개 unit/integration 테스트, source organizations/operations/roles E2E 통과. `release/assignment-lookup-fix/win-unpacked/OMNIS.exe`에서 organizations(제20전비·제2여단 각각 10명·선택/저장·재시작·두 해상도), operations, smoke를 통과했다. 1366/1920 캡처를 확인했다.

설치본: `release/assignment-lookup-fix/OMNIS Setup 1.0.0.exe`, 122,072,132 bytes, Authenticode `NotSigned`. Installer SHA-256: `128580A672C326FAB55FD5A0DB83D27F3A4122C83620566119F19BE59EEDD137`. Unpacked EXE SHA-256: `29B5234EB31E824D20582299C9D91410E168210CFC8A9AB343067C244D08121F`. 새 macOS 실행·clean PC 설치/제거·실제 외부 AI 호출은 수행하지 않았다.

## 추가: 부대별 가상 담당자와 입력 점검 여백

DB v8의 `organization_members`는 실제 부대와 **가상 담당자**를 연결한다. 기본 22개 부대에 각각 10명씩 등록한다: 비행단급 130명, 여단급 30명, 전대급 60명, 합계 220명. 기존 로그인 사용자 11명은 유지한다. 부서 미등록 부대에도 담당자는 존재하지만 내부 부서를 임의로 생성하지 않는다.

- **시스템관리 → 조치부서 → 부대 담당자**에서 부대급·부대를 선택하여 10명 명단과 계급을 확인한다.
- 고장 상세에서 소속 부대·조치부서를 선택하면 해당 부대 담당자가 선택 목록에 표시된다. 부대 변경 시 저장 전 담당자 선택을 비워 타 부대 인원 오배정을 막는다.
- 이름·계급은 시연용으로 만든 인물이다. 군번·전화번호 등은 생성하지 않는다. 업무 배정용 연락 명부이며 비밀번호가 없어 로그인할 수 없다. 실제 등록 사용자 계정은 그대로 사용할 수 있다.
- 재실행·seed 재실행 시 중복 생성하지 않고 기존 담당자의 수정 이름·비활성 상태와 업무 배정을 보존한다. 새로 등록한 비행단/여단/전대급 부대도 가상 담당자 10명을 제공한다.
- 고장 상세의 담당자/배정 영역과 **입력 점검 박스 사이에 20px 여백**을 추가했다. 다른 화면의 입력 점검 배치는 유지한다.

아래 v7 설치본·57개 테스트 기록은 이전 버전 기록이다. 이번 v8 수정의 최종 결과는 문서 끝의 별도 기록을 참고한다.

## 사용 순서

1. 고장관리 → 신규 고장 접수에서 요청부서와 증상을 입력하고 저장한다.
2. 조치부서를 지정하지 않은 새 접수의 목록에는 **미지정**이 표시된다. 담당자만 지정한 경우에도 조치부서는 미지정이다.
3. 상세 → 조치부서 지정에서 부대급 → 실제 소속 부대 → 조치부서를 선택하고 **조치부서 배정**을 누른다.
4. 배정을 해제하려면 **조치부서 미지정** → **미지정으로 저장**을 누르고 확인한다.
5. ADMIN은 시스템관리 → **조치부서**에서 누락 부서 추가, 명칭 수정, 새 배정 사용 여부를 관리한다. 부대명 검색 또는 새 부대명을 직접 입력할 수 있다.

선택·검색만으로 배정되지 않는다. 담당자는 별도 선택하며 가상 담당자를 실제 부대원으로 자동 연결하지 않는다. 배정/해제 및 AI 추천 반영으로 요청부서를 변경하지 않는다. 해제 시 배정(ASSIGNED) 상태만 분류(TRIAGED)로 돌아가며, 진행 중 상태와 처리 기록을 지우지 않는다.

## 데이터와 권한

- 요청부서: 기존 incidents.department. 조치부서: incidents.team_id → maintenance_teams.name. 목록·상세는 배정된 부서 이름을 사용하며 요청부서로 대체하지 않는다.
- v7: organization_units, team_organizations 추가. 기존 표·행·배정·첨부자료를 삭제하거나 초기화하지 않는다.
- 배정/해제는 ADMIN·OPERATOR, 디렉터리 변경은 ADMIN만 Main에서 허용한다. payload는 Zod로 검증한다.
- 부서를 사용 안 함으로 바꾸면 신규 배정을 차단하고 기존 배정·이력은 보존한다. seed 재실행은 관리자 수정·사용 안 함을 덮어쓰지 않는다.
- 기존 유선·무선·사이버 정비반과 세 가지 AI 추천 코드는 호환성을 위해 유지한다. 외부 AI가 임의의 실제 부대명이나 새 부서 ID를 생성하지 않는다.
- 기존 버전에서 이미 덮어쓴 요청부서는 근거 없이 자동 복원하지 않는다. 원본을 확인한 뒤 접수 수정에서 바로잡을 수 있다.
- 디렉터리 주소는 출처 기록용으로 저장하며 앱 시작·화면 열기 시 인터넷으로 자동 조회하지 않는다.

## 공개자료 반영 범위

22개 실제 부대명(비행단 13·여단 3·전대 6)을 등록했다. 공개자료에서 확인한 13개 조치조직과 기존 공통 정비반 3개를 선택할 수 있다. 제7항공통신전대는 통신부대 자체를 조치조직으로 등록했으며 확인하지 않은 예하 부서는 만들지 않았다.

부대명 확인과 내부 부서 확인을 구분한다. 1·2·3미사일방어여단 등의 세부 정보통신 편제는 이번에 확보한 자료로 확인하지 못해 부대명만 등록했다. '모든 부대의 현행 내부 편제가 검증 완료되었다'는 뜻이 아니다. 내부 부서명을 추정하여 일괄 복제하지 않는다. 관리자 확인 명칭은 **관리자 등록**, 기본 출처 명칭은 **공개자료**로 구분한다.

아래 자료는 공개 기사·보도에 나타난 명칭을 확인한 근거이며 현재 편제의 공식 인증은 아니다. 일부 자료는 오래되었고, 직접 페이지 열기가 시간 초과한 경우 검색 색인에 제공된 본문·발췌를 확인했다. 기준일을 함께 보존하므로 현행과 다를 경우 관리자가 수정할 수 있다. 인명·군번·연락처·위치·실제 임무 현황은 수집하지 않았다. 120분 처리시간 등의 기존 앱 기본값은 실제 부대 실측치가 아니다.

## 근무편성표 부대별 담당자 조회 (2026-10-28)

근무/지시사항 화면과 근무 등록·수정 창에 부대급/소속 부대 검색을 제공한다. 등록·수정 담당자는 `organizations:members`로 직접 조회하고 조회 중·오류·빈 명부를 안내한다. 부대가 바뀌면 기존 담당자 선택을 지우고 이전 부대의 늦은 응답을 무시한다. 기존 담당자를 변경하지 않는 수정도 가능하다. 가상 명부는 이름 옆에 가상으로 표시한다.

근무 편성표에 소속 부대 열을 추가하고 상단 부대 필터를 편성표와 오늘의 근무에 함께 적용한다. 전체 부대에서는 기존 담당자 선택 방식도 유지한다. 여러 명 등록은 같은 담당자 중복을 막으며, 담당자·직책이 없거나 조회 중/실패한 상태에서는 저장하지 않는다. DB 테이블이나 기존 근무 기록을 변경하는 migration은 필요하지 않으며 기존 ADMIN/OPERATOR/USER 편성 권한을 유지한다.

사용: **근무/지시사항 → 근무 등록 → 부대급 → 소속 부대 → 담당자 선택 → 직책 입력 → 저장**. 편성표 상단에서 부대를 선택하면 해당 부대의 기존 근무를 조회한다.

자동 UI 검증: `pnpm test:e2e:duty-units`는 격리된 프로필에서 비행단/여단/전대 각각 10명 조회, 2명 등록, 중복 선택 방지, 편성 수정, 부대 필터, 1366/1920 화면을 검증한다. 실제 사용자 DB에는 테스트 근무를 등록하지 않는다.

### 편성 기록이 없어도 메인 화면에 명부 표시

부대 선택 시 등록된 근무만 필터하던 조회 범위를 보완했다. 선택한 부대의 활성 담당자를 별도 API로 읽어 상단 부대 담당자 명부 카드에 전원 표시하고, 가상 담당자 표시와 오늘 편성 여부를 안내한다. 명부의 근무 등록 버튼은 해당 담당자를 미리 선택한다. 근무 기록은 자동 생성하지 않는다. 근무 0건인 제20전투비행단에서도 명부 10명이 표시되는 경우와 명부에서 등록 창 진입을 E2E에 추가했다.

### 명부 배치 및 오늘 배지 개선

명부 10명을 기본 5열×2행으로 균등 배치하고 이름/계급, 편성 상태/등록 동작의 위치를 통일했다. 반복 문구는 줄이고 계급과 가상 표시는 보조 글씨로 분리했다. 날짜 열은 최소 210px로 확보하고 오늘 배지와 날짜를 줄바꿈·축소하지 않도록 처리했다. typecheck/lint/build 및 duty-units E2E를 통과했고 1366×768·1920×1080에서 5명씩 두 줄, 카드 넘침 없음, 오늘 배지의 셀 내부 전체 표시를 검증했다.
